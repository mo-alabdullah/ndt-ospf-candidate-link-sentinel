\section{Introduction}

Network digital twins (NDTs) are increasingly used to evaluate candidate network changes before deployment, but their value depends on timely agreement with the represented network~\cite{zhou2026ndtarch,zhou2026datacollection}. A twin can be correct about topology, routing state, and configuration while stale about a performance property of the link that a change will activate. For routing automation, this creates a false-safe failure mode: the simulated route is correct, yet the operational service-level objective (SLO) is violated.

We study this failure for OSPF link-cost reconfiguration. OSPF selects paths from configured link metrics~\cite{moy1998ospf}, and weight changes are a standard traffic-engineering mechanism~\cite{fortz2000ospf}. Formal configuration analysis and consistent-update systems address reachability, control-plane correctness, and transition behavior~\cite{fogel2015analysis,beckett2017verification,prabhu2020plankton,reitblatt2012updates}; they do not by themselves establish that the performance state represented in a twin remains current.

Our controlled testbed contains structurally identical operational and twin networks. Hidden latency is applied only to the operational direct link that becomes preferred after a candidate OSPF change. Both environments install the same next hop, but at 30 ms per-direction hidden delay the twin predicts 0.166 ms end-to-end RTT while the operational network measures 66.274 ms against a 50 ms SLO. We then ask whether pre-deployment measurements can detect this localized drift without reducing the gate to complete abstention.

The contributions are fourfold: (1) a reproducible route-consistent false-safe NDT case; (2) a negative result showing that tested residual-only gates are unsafe or vacuous under mixed delay schedules; (3) a candidate-link sentinel that uses the proposed configuration to choose a targeted pre-deployment measurement and correct the twin prediction; and (4) separated validation and held-out reporting that distinguishes deployment accuracy from conformal predictive coverage. The broader design pattern is to use candidate-configuration semantics to identify and measure the operational resource most likely to invalidate a twin prediction. The scope remains deliberately narrow---one three-router OSPF topology, one candidate link, and latency drift---so the result validates this pattern only in the tested regime rather than at production scale.
